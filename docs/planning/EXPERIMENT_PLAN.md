# Experiment plan for reviewer advice lifetimes

Protocol status: proposed local-run protocol, 8 October 2026. No real API experiment is reported. The researcher runs paid or model-generating stages locally after reviewing their configuration. This plan does not specify or endorse a particular gateway, credential, model, price, or training procedure.

## 1 Research question and acceptable claims

After a controller executes a reviewer-proposed action, does the continued applicability of the same reviewer packet affect later preservation of goals already achieved during an unfinished task? The primary intervention retains every packet word but changes a matched status header after the packet's declared call requirement is fulfilled. Whole-packet removal is a necessary secondary comparison.

This is an empirical study of presentation policies. State restoration, immutable receipts, feedback expiry, context management, and task-clustered risk differences are enabling methods, not claimed methodological inventions. The existing novelty audit is a bounded literature assessment, not proof of a first discovery. No claim that reviewers generally harm agents, that all feedback becomes harmful, or that an internal cognitive mechanism has been identified is precommitted.

Distinguish three hypotheses:

- H1: persistence of a reviewer packet can change terminal unresolved-loss risk relative to a factual receipt alone. Estimate its sign; do not assume harm.
- H2: C improves preservation relative to P while staying within the prespecified tolerance for loss of official task completion.
- H3: the effect concerns advice applicability, beyond generic context shortening, wrapper wording, or stopping work early. This requires same-text C/P plus competing controls and outcome-blind scope annotation.

An H1 null does not falsify H2: deleting the whole packet can remove useful information as well as harmful guidance. An imprecise interval does not establish equivalence. A useful negative or narrowly scoped result is acceptable.

## 2 What the release actually establishes

Existing frozen evidence comprises:

- Seven scripted Telecom witness trajectories, fourteen fresh-process restores, and 42 checkpoint/tool pairs with 84 READ transitions.
- A factual receipt adapter with 37 named tests and six fresh-process checks.
- A separate lifetime overlay with 40 named tests and 31 fresh-process checks, including P/R/C serialization and common-prefix restoration.

These counts are software tests, not independent tasks in an effectiveness study. Scripted success rewards must never appear in a model performance table. The implementation has not established actual provider wire semantics, token matching, natural actor/reviewer/user behavior, broad mutation support, natural repair prevalence, or formal power.

The seven tasks were inspected and used during development, including three originally labeled test by upstream. All seven are now exposed development/readiness material for this project. They cannot become a new held-out set merely by preserving their upstream split label.

## 3 Gates and stopping rules

Each gate produces a separate signed-by-hash receipt with source/configuration hashes, concrete supported scope, checks run, failures, and unresolved limitations. A later gate cannot turn a prior fixture into a natural observation.

### G0 Repository and offline readiness

Required: reproducible source pins and licenses, fresh local environment instructions, default no-network dry-run, all eight arm definitions, event schema validation, deterministic fixture restore tests, negative leakage tests, real-versus-fixture labels, all-draw accounting, and an honest capability report.

The historical launchers depend on their prepared environment. Packaging a directory is not proof that a clean clone installs successfully. The new release must say which clean-clone steps were tested and which were only documented. Do not copy an existing virtual environment or cache into Git.

### G1 Provider wire readiness

A researcher-opted-in, request-limited wire-smoke test confirms the exact chosen provider/model/API interface. Capture the post-SDK request payload with authentication redacted: role order, header position, tool catalog, call/result pairing, exact packet bytes, first P/R/C equality, later P/C permitted diff, and later R removal. Verify actual usage, retries, request identifiers, error mapping, and response validity.

Character-length equality is not provider-token equality. Compute the actual tokenizer result when available and report residual token differences. If the provider's tokenizer or server-side normalization is opaque, record that limitation; do not claim exact semantic or information matching. Capture what was actually sent, while distinguishing unobservable server processing. A generic local message object is insufficient evidence.

This gate contains no benchmark effect claim. If roles are moved, rejected, or merged, stop the dependent experiment and version the mapping before recollecting data. Do not silently switch providers during a block.

### G2 Natural development and coverage pilot

Generate fresh actor and legitimate user trajectories using a fixed reference policy. Trigger review using only a frozen public rule; preserve every task start, no-trigger episode, raw draw, invalid draw, tool error, early terminal common segment, retry, and interruption.

The seven exposed fixtures may support an initial natural plumbing pilot, but their authored success paths must not be replayed as model continuations. A suggested bounded first pass is one reference trajectory per exposed task, at most one root per trajectory, one reviewer draw per root, two independently generated common first-exposure segments, and two suffix continuations per segment for P/R/C. For the other arms, use four independently generated root continuations. These are debugging defaults, not an adequate power calculation or a promise of seven usable roots. Configured request/step limits or an optional spend cap may prevent completion; report the resulting incompleteness.

Use a separate expanded development partition to measure task-family variation, public-trigger frequency, acquired-goal coverage, changed/valid proposals, normal tool return, immediate preservation, genuine local-repair incidence, effect variance, retry rate, token cost, and feasibility of held-out sampling. Do not stop or expand because one arm happens to look favorable.

### G3 Natural repair and mutation validity

**The current seven READ-only intervention fixtures do not establish natural local repair.** Their two predicates (connectivity and excellent speed) are nested, their pending action is a customer lookup, and their reference suffixes are authored. A successful READ cannot by itself be a repaired physical state; its immediate preservation is largely structural.

Before a formal paper claim about post-repair achieved-goal preservation, extend and validate natural workflows containing relevant state-changing operations, meaningful unfinished work, and publicly grounded requirements. A separate READ-only study can estimate a clearly scoped query-advice presentation effect after G1/G2; it must not be renamed evidence that useful repairs later become harmful.

Mutation support requires per-tool and per-boundary tests: exact state restoration, auxiliary state, nonzero native error budgets, participant routing, side effects, response integrity, fresh-process isolation, and strict official evaluation. The current common-prefix fixture test does not certify arbitrary natural checkpoints. Unsupported suffix paths are infrastructure-invalid observations; do not modify the actor's permitted tools without declaring that different task setting.

Priority extensions are listed in the fault-family manifest. Agent-side carrier changes and user-side device changes have different ownership. Device tools must be called by the legitimate user simulator after normal dialogue, never by an actor impersonating the user. Billing/UUID creation, shared VPN defaults, active deadlines, multi-call proposals, multi-slot review, audio, and streaming stay blocked until separately validated.

Map each scored goal before outcomes are inspected to: semantic requirement, public authority source, observable evidence, temporal mode, hidden evaluator implementation, and ambiguity. Include non-nested goals where valid official tasks permit them; do not fabricate broad coverage by counting nested predicates or near-identical personas independently. Cross-domain conclusions require additional verified domains.

### G4 Confirmatory freeze and local run

Freeze task and family partitions, model/provider versions, reference policy, all prompts, reviewer contract, public trigger, root sampling, arm set, closing rule, maximum budgets, repetition schedule, seed scheme, retry policy, prices, primary endpoint, meaningful gain delta, completion tolerance epsilon, interval method, secondary multiplicity policy, and stopping rule. The researcher records operational limits and, if desired and price-verifiable, a monetary ceiling before live launch. No additional approval from an assistant is required for the researcher to run locally.

A run labeled confirmatory must refuse null/unfrozen scientific-design fields and unresolved G1/G3 evidence checks. Exploratory local execution remains available when the implemented runtime can support it; an evidence gate is not an artificial authentication or assistant-approval gate. Select final task counts and repetitions using development variance and cost estimates. Use a fixed planned sample or a genuinely prespecified sequential design; the minimum implementation uses a fixed sample and no effect-dependent early stopping. A configured operational cutoff or optional spend ceiling stops calls, but yields an incomplete study rather than silently changing the estimand.

### G5 Episode-start utility and robustness

Evaluate P and C from ordinary task starts using the same initial task distribution, public trigger, single review slot, and prespecified resource limits. Include no-trigger episodes in utility. These policies encounter their own trajectories; do not substitute only favorable diagnostic roots. Complete necessary controls before making a practical applicability claim.

## 4 Dataset and task manifest

Source: official sierra-research/tau2-bench commit `4ce7c0397c1eb65c9bbe59aeacfe1ca44a1cd699`, tau2 package 1.0.1, later Telecom implementation called tau3 in the frozen evidence. Cite the original tau2 benchmark paper separately from the pinned code.

The frozen audit reports 2,285 full tasks, 114 base tasks, 74 train, 40 test, and 20 small. These are overlapping selections, not additive independent populations. The conservative staged-goal metadata filter found seven base candidates, 45 full candidates, and zero small candidates. Static candidate counts do not establish natural checkpoint frequency.

`manifests/tasks_readiness.json` records the seven exact task IDs, original split, task hashes, and fault signatures. `manifests/candidates_static.json` records the 45 candidates for audit, not as a formal sample. `manifests/fault_families.json` identifies existing support and proposed mutating extensions.

All tools execute inside the local synthetic benchmark environment. Nothing in this protocol authorizes connecting real telecom, customer, billing, or payment accounts.

Selection rules:

1. Pin source data and inventory before collecting trajectories. Preserve the official reward basis; some Telecom tasks require ACTION in addition to ENV_ASSERTION. Never replace official grading with only the two convenient goal predicates.
2. Reserve all already explored tasks/families for development. Group persona variants and equivalent underlying fault configurations before splitting. A canonical sorted fault signature is a minimum grouping, with broader overlapping mechanism families used in sensitivity analysis.
3. Create an explicit prospective family partition for any new sample. Record the deterministic grouping/split seed and all exclusions. Do not claim unexamined outcomes prove there was no design exposure; label metadata-screened candidates honestly.
4. Use a fixed public trigger such as the first supported single pending actor tool call after a prespecified public interaction condition. A concrete conservative development default is the first supported single actor READ proposal after at least two completed public agent-tool events, with at least one legitimate user reply since task start. It uses no private goal information and may often select roots with no acquired goal, which must remain in the funnel. Freeze this exact predicate as `public_single_read_after_two_tools_v1` before a pilot, or version any different rule before collecting data. It is a plumbing default, not a claim to be an optimal trigger for repair. Do not wait until private goals look favorable. Record the root selection probability; a default first-eligible rule gives one root per trajectory. Any multiple-root extension needs a fixed cap and declared sampling weights.
5. Keep a complete funnel: attempted starts, valid natural prefixes, public triggers, selected roots, acquired-goal structure, raw q classes, successful dispatch, immediate preservation, second-boundary reached, terminal-evaluable blocks, and full official completion.
6. Candidate lists selected using evaluator metadata support that selected task population only. The runtime public trigger remains oracle-free; task-population selection and runtime selection are distinct limitations.

## 5 Goals and information firewall

For root x, let Gplus contain only goals that were false at an earlier observed state in this episode, are true at x, and remain required through termination. Initially true conditions form a separate maintained-initial-state stratum. At least one newly achieved goal and one unmet goal define the unfinished-goal diagnostic subgroup; this hidden-label condition must not decide online review or closure.

For each arm z, L(z) is 1 if any Gplus goal is false at the native terminal state. Set L=0 for empty Gplus in the all-root estimand and report its prevalence. U is the fraction of Gplus lost and is undefined, not zero, when Gplus is empty. Official completion Y is separately computed with the complete upstream contract. Native step/error exhaustion is a real terminal outcome. Infrastructure loss of the terminal state is missing evaluation, not success and not automatically actor failure.

Record immediate loss, first subsequent regression, observed transient loss, recovery, recurrence, and terminal unresolved loss. A temporary interruption of a terminal-state requirement is not automatically damage; always-required invariants have their own violation endpoint. Evaluate only at declared captured state boundaries and acknowledge that unobserved within-tool transitions are not measured. Align comparisons by task phase or consumed resources, not by treating different branches' step numbers as identical times.

Runtime actor/reviewer/controller projections may contain public conversation, permitted tool schemas, pending public a0, actual public returns/errors, original task requirements, and factual receipts. They must not contain private goal vectors, evaluator names/thresholds, answer keys, task IDs, fault-family labels, hidden database snapshots, reference actions, future user replies, shadow outcomes, or another branch's future text.

The user simulator retains only its legitimate original scenario and its own branch state/history; it receives neither controller receipts nor reviewer packets nor additional evaluator labels. Public goal statements may be retained when genuinely disclosed. Do not promote an undisclosed threshold into the prompt because the scorer uses it.

Run shadow evaluation on isolated copies after the immutable draw is saved. Assert it cannot mutate the deployment branch. Allowlist request fields, use evaluator/source canaries, and record effective request hashes; canary success does not prove arbitrary text contains no secret. Public benchmark fixtures are synthetic, but local output still receives a privacy review before sharing.

## 6 Full arm semantics

All arms preserve native task instructions, permitted tools, termination rules, remaining step/error budgets, and honest action provenance. The receipt is actor-only and never a forged model action. Canceled a0 is removed from pending native calls without fabricating a successful/canceled tool response for it. An executed revised action has its own bound call identity.

| CLI arm | Paper name | Selected action and subsequent input | Purpose |
| --- | --- | --- | --- |
| B_bare | B_native | a0, native action/result representation; no controller receipt or reviewer packet | Native instrumentation control |
| B | B | a0, factual controller receipt only | Instrumented baseline |
| S | S | One real self-reconsideration call using the actor, public context, a0, and frozen prompt; selected self-revision or declared invalid fallback; factual receipt | Extra-deliberation control |
| A | A | Same frozen reviewer a1 and real result as P0/P/R/C; factual receipt; no packet/header | Action-and-information baseline |
| P0 | P0 | Same a1; exact raw packet persists; no new header | Legacy packet exposure and wrapper calibration |
| P | P | Same a1; exact packet and matched neutral header persist | Primary comparator |
| R | R | First request exactly P; after one valid actor response, omit entire packet and dedicated header | Whole-packet exposure baseline |
| C | C | First request exactly P; subsequently retain exact packet and change only matched header if the public close rule is true; otherwise remain exactly P | Primary treatment |

S is not yet evidenced by a natural self-reconsideration result. Freeze one additional call, its token ceiling, parsing and fallback rules, and whether self-revision prose is retained. The minimal contract uses selected self-action plus factual receipt, with raw self-reconsideration output audit-only. This is a proposed operational completion of the paper's control and must be documented before data. Match the review opportunity's call/token allowance, while reporting actual cost; do not call equal maximum tokens equal realized cost. S may choose a different action; it does not belong to the equal-a1 family.

A/P0/P/R/C use the same single frozen q, selected action and captured result, with equivalent restored post-action states. B_bare/B share a0 and its native result while differing only in intended receipt instrumentation. S has its own self-reconsideration. Do not force a1 into B or S to manufacture equal-action controls.

### Public success-only closure

Capture the declaration before dispatch: target action identity, scope, instruction class, and close condition. The minimal supported close rule is `action_local` + `execute_target_call` + `normal_tool_return`, bound to the actual selected action ID and an observed matching tool result with `error=false`.

A normal result means this call requirement was fulfilled. It does not mean the underlying issue was fixed, the suggestion was correct, or the user task is complete. C waits through one valid actor response even when this rule is already satisfied. Starting with the second actor request, it changes only the status sentence. Failed calls, mixed/ongoing/unresolved scope, unmatched targets, or unknown conditions retain P. Scope fields are not a perfect semantic classifier: outcome-blind prose violations are logged and retained; a misleading action-local declaration can still close.

R removes the whole packet after a valid response, including after a tool-error fixture, because its treatment is exposure count. Rendering, transport errors, and invalid actor responses do not consume this exposure. Restart cannot grant a second first exposure. Native actor echoes of the packet remain: this is no longer attaching a packet, not erasing its past influence.

For malformed JSON/declarations/arguments or out-of-scope actions, preserve the one raw draw and take original-action/no-packet fallback. Never redraw until valid. An unchanged action with feedback remains an intervention. A valid-schema action rejected by the official tool remains a tool error, not a formatting exclusion. Semantically mixed but well-formed declarations remain in the ledger with their predefined behavior.

## 7 Shared segments and independent continuations

The unit is task i, natural root j, one frozen original proposal a0, and one frozen reviewer draw q. Distinguish its task, fault family, reference-trajectory, root, draw, common-prefix-repeat k, suffix-repeat r, arm, provider-attempt, and physical-call IDs.

For each k:

1. Restore the same validated post-a1 state.
2. Generate the identical first exposed P/R/C request once and obtain one valid actor response.
3. Execute all resulting native actor tools and legitimate user events until the next actor-request boundary. These events are genuinely common, because treatment policies have not differed yet.
4. Save complete environment/participant state, histories, routing, auxiliary tool state, remaining budgets, applicable clocks, RNG and policy exposure state.
5. Restore fresh objects for each P/R/C arm and each suffix repeat r. Generate future actor and user responses independently. Never reuse authored suffixes or copy post-divergence user replies.

If the common segment terminates, record the same observed endpoint for these arms, with no invented fork. Keep the root in every denominator; virtual duplicate suffixes must not inflate its effective sample size. Use a landmark subgroup only as a labeled secondary analysis.

Repeat the common segment across k. Infinitely many suffixes after only one sampled segment do not estimate the full policy distribution. A/P0 and other arms with different first requests generate their own continuations from the appropriate root state; they cannot inherit P's first response. Remote provider seeds are recorded but never assumed deterministic. Snapshot equality concerns reproducible initial states, not identical stochastic future worlds.

Randomize and interleave complete arm blocks across provider time, retaining shared-segment dependencies. Freeze model sampling parameters, separately seed environment initialization, root selection, allocation/order, reviewer sampling where supported, common segments, suffixes, and bootstrap analysis. Record unavailable provider seed support. Model/version drift triggers a recorded block stop or a prespecified version stratum, never silent pooling.

## 8 Estimands and inference

Primary fixed-root estimands over frozen reference distribution Dref, all single raw q draws, and continuation randomness:

- Delta_root = E[L(P) - L(C)], positive for lower loss under C.
- DeltaY_root = E[Y(C) - Y(P)].

Compute arm risk within root over the full nested k/r design; average roots within task, then tasks equally. Log root sampling weights if the design is unequal. Task and family identifiers remain evaluator-side. Do not treat checkpoints, nested goals, or repeated suffixes as independent task samples.

Use task-cluster resampling of complete blocks for primary intervals; retain all nested common segments, arms, and suffixes together. Provide broader fault-family aggregation/sensitivity because overlapping templates reduce effective diversity. With very few tasks/families, show individual task results and explicitly unstable intervals. Do not create apparent precision by counting repeated clones as new tasks. Predeclare confidence level and number/seed of resamples; a proposed default is 95% intervals and 10,000 task-cluster resamples, to be frozen before confirmation.

Diagnostic stratum Omega is fixed from x and q in an isolated shadow execution: Gplus nonempty, public format/scope valid, a1 differs from a0, no actual tool error, and all protected goals hold immediately afterward. It may not depend on terminal success, later regression, a branch's future, or the direction of a measured effect. Report its coverage and compare P/C, P/R, P0/A, and A/B there. A/B includes action substitution and changed information; it is not a pure action effect. These policy effects are not natural direct or indirect effects and do not prove individual counterfactual harm.

For episode-start runs, J(z)=E[Y(z)] and DeltaJ=J(C)-J(P), with all starts including no-trigger episodes. The ever-achieved set may differ by policy, so episode-start achievement/loss descriptions are not same-goal causal contrasts.

Every assigned root remains in the disposition ledger. Analyze available endpoints with explicit denominators and report incomplete-block sensitivity bounds. For binary L, fill missing P=0/C=1 for the least favorable improvement bound and P=1/C=0 for the most favorable bound, preserving task weighting; use analogous bounds for completion. Do not silently complete-case select, impute infrastructure errors as successes, or redraw q after an outage.

## 9 Pilot precision and resource planning

The development pilot estimates public coverage, event frequency, between-task/family variation, shared-prefix versus suffix variance, call/latency distributions, retries, and actual provider costs. Its selected signals are exploratory. Seven related READ tasks cannot establish adequate sample size for formal claims.

Choose the confirmatory sample and k/r allocation using task-cluster resampling/simulation informed by the expanded pilot, not an IID binomial calculation over all continuations. Report assumed effect sizes, confidence-width target, event-rate uncertainty, delta, epsilon, dropout scenarios, and budget feasibility. Prefer broader independently held-out families over excessive same-root suffixes when between-task variation dominates. If feasible precision cannot be achieved, label the study exploratory or narrow its stated population before new collection.

Support an improvement claim only if the prespecified lower confidence bound for Delta_root exceeds delta and the lower bound for DeltaY_root exceeds -epsilon. Treat this as the frozen joint success criterion; do not select whichever endpoint looks best. Predeclare a hierarchy or multiplicity adjustment for confirmatory secondary contrasts; otherwise mark them exploratory. No actual delta, epsilon, price, sample size, or effect is claimed here; null configuration fields must block a confirmatory launch.

## 10 Costs failures and retries

Every physical model attempt is appended before/after dispatch with role, request digest, provider response/call identity where returned, tokens including cached/reasoning fields when available, elapsed time, result/error class, retry linkage, and currency cost source. Preserve raw responses privately. Never log Authorization headers or secrets.

Physical experiment cost deduplicates only the same actual physical call. Logical deployment cost assigns each arm the reference preparation/reviewer/common-prefix costs it would actually incur in deployment. B/B_bare/S do not inherit experimental reviewer cost for a q they would never request. S does incur its own self-reconsideration. Report both totals and the allocation rule. Artificial TEST_UNITS never become tokens or currency; missing usage is unknown, not zero.

Retry transport/rate-limit/server failures only under a frozen cap and backoff policy. Malformed reviewer output is an observed draw, not permission to sample again. After a valid response is persisted, retrying parsing or rendering must not create another model call. If a connection is lost after possible server execution, record outcome/charge as unknown; do not pretend identical request bytes prove the server deduplicated it. Charge retries conservatively and preserve all attempts. Never blindly retry an uncertain mutating tool execution; use verified state/operation identity or mark the block infrastructure-invalid.

Configurable request, step, retry, and per-response limits apply before dispatch and default to modest smoke-test values. There is no required experiment-wide token budget. If the researcher selects a monetary ceiling, reserve a conservative bound for each call and count failed/unknown-billed attempts conservatively; if that ceiling cannot be enforced without prices, refuse that particular ceiling configuration rather than claim protection. With no monetary ceiling and unknown pricing, local live runs may proceed under their operational limits; report actual tokens and cost as unknown. Stop cleanly at any selected limit and retain unfinished blocks.

Minimum statuses: completed; native_max_steps; native_error_limit; native_terminal_failure; no_public_trigger; invalid_draw_fallback; unsupported_path; restore_mismatch; provider_error_exhausted; provider_result_unknown; actor_output_invalid; budget_stopped; user_interrupted; evaluation_error. Status and evaluation availability are separate from L/Y outcomes.

## 11 Required controls and falsifiers

Before interpreting C/P as scope-specific evidence, include or explicitly defer:

- B_bare/B instrumentation effect and P0/P wrapper calibration.
- A and R information/exposure controls; S equal-opportunity reconsideration.
- A matched-token neutral wording control and generic non-review context reduction under the same position/role constraints.
- Latest-feedback retention and a frozen fixed-TTL policy.
- Public goal checklist and ordinary tool/user-mediated terminal recheck, with their actual costs.
- Premature versus delayed closure timing, including useful ongoing-scope negative controls in a separately implemented extension.

Generic deletion must not remove mandatory user instructions or real safety/authorization constraints. Privileged goal-gated or rollout-oracle methods can be offline reference lines only. Factual receipt removal is a diagnostic information ablation, not a recommended deployment configuration.

Falsifying or claim-limiting outcomes include insufficient natural incidence; no meaningful C/P improvement at adequate precision; unacceptable completion loss or delay; generic pruning/wrapper changes explaining the benefit; benefits appearing only after hidden-label filtering; instrumentation effects comparable to the claimed gain; or gains restricted to tiny constructed/falsely critical cases. Report the corresponding narrow conclusion rather than changing the primary comparison after results.

## 12 Outputs and reporting

Produce versioned, machine-readable manifests and tables before narrative interpretation:

1. Run disposition and complete coverage funnel, including zero eligible roots.
2. Per-task/per-family arm counts, loss and completion rates, missingness, and costs.
3. Main all-root Delta_root/DeltaY_root with intervals and sensitivity bounds.
4. Separate episode-start J/DeltaJ table with trigger coverage and resource use.
5. Clearly labeled Omega diagnostic contrasts, instrumentation and wrapper calibration.
6. Immediate, transient, recovered, recurrent, and terminal loss summaries; scope violations; close/retain frequencies and closure errors where outcome-blind annotations exist.
7. Provider request-format/token-difference audit, retry/error report, and physical/logical cost reconciliation.
8. Prespecified case sample including supporting, null, and contrary examples, with actual action/receipt histories and official evaluation basis. Do not infer internal reasoning mechanisms from textual phrases.
9. Reproducibility receipt: Git/source/config/prompt/task/data hashes, software/runtime inventory, models, timing, seeds, planned versus achieved sample, deviations and stop reason.

A dry-run produces structural fixtures marked `scripted_fixture`, empty real-result tables, and a zero-real-experiment status. It must not display fabricated estimates or label example numbers as observations. A report with no live data should say `not_run` for model outcomes.
