## 0 臂投影语义（核验自 engine.py project()/execute()）

| 臂 | 执行回执 | 建议包(packet) | 生命周期头(header) | 采用动作 |
| --- | --- | --- | --- | --- |
| B_bare | 否（原生 step，无投影） | — | — | 原始 |
| B | 是 | 否 | 否 | 原始 |
| A | 是 | 否 | 否 | **Reviewer 选择** |
| S | 是 | 否 | 否 | **自我重考虑(Actor 模型)** |
| P0 | 是 | 是 | **否** | Reviewer 选择 |
| P | 是 | 是 | neutral（持续） | Reviewer 选择 |
| R | 是 | valid_responses≥1 后**移除** | 移除前 neutral | Reviewer 选择 |
| C | 是 | 是（保留） | valid_responses≥1 且 closable 后 neutral→**consumed** | Reviewer 选择 |

由此 §11.2 A 项的预定对比各自隔离一个机制：B_bare/B=回执；S/B=额外思考；A/B=Reviewer 动作；
P0/B=建议包；P/P0=生命周期头；R/P=一次履行后移除包；C/P=关闭生命周期。

## 1 关键背景：已测得的机制空档（决定各消融的杠杆）

真实证据（联调 `development/e2e-live-integration-001` + 三轮 reference）显示：在 roaming-protectable 池上，
**Reviewer 极少改变 Actor 动作**（联调 8 episode 的 draw 分类为 6×unchanged、0×valid_changed），且任务足够简单，
B/P/R 完成率均饱和于 J=1。含义：

- A/S 臂（依赖 Reviewer/自我改变动作）将 **≈ B**；P0/P/R/C 之间的差异仅来自注入的**包/头文本**，
  而该文本在联调中未产生系统性效应。
- 因此凡「**预设存在稳健主效应、再追问由何种包装/上下文/措辞解释**」的消融（B/C/E/F/H），在本池上
  **杠杆接近零**：没有稳健效应可供分解。这是**科学限制**（池中机制近乎惰性），非平台缺陷。

| **G** 持续有效与错误声明 | 关闭是否错误撤销仍有用建议 | **部分可实现**：对自然 draw 的 `declaration`/`closable` 做**结局盲审计**（ongoing vs closable、失败返回、混合建议、声明不符），无需新臂 | **实现为分析诊断**；构造范围违规案例另作机制测试，与自然发生率分开（line 416） |
| **D-3** 固定 TTL=3 | 3 次有效响应到期 | 需新机制（计数至 3 的移除规则） | 记录限制：需 engine 改动；且预设 R 有稳健效应可对比，本池杠杆近零 |
| **B** 中性头改写 | 一般包装措辞是否解释变化 | 需新投影变体（替代中性头文本） | 记录限制：需 engine 改动；联调中头文本未产生效应（P=R=B=1.0），无稳健效应可归因 |
| **C** 普通历史删减 | 是否仅因上下文变短 | 需新删减机制；tokenizer 若不可用改为**明确标注的 byte/字符长度匹配**，放弃「严格 token 匹配」表述（line 410） | 记录限制：需 engine 改动 + 长度匹配实现；预设 R 有效应可归因于长度，本池 R≈P 杠杆近零 |
| **E** 事实化改写 | 状态标记 vs 重写建议 | 需新投影变体（把建议改为事实记录）+ 额外调用计入成本 | 记录限制：需 engine 改动；预设建议内容影响动作，本池建议极少改变动作 |
| **F** 公开目标清单与终局复核 | 更强状态维护是否解释/替代收益 | 需新机制（注入公开清单 + 终局额外复核调用），额外模型/工具调用全部计入成本，不用隐藏 evaluator 提示模型 | 记录限制：需 engine 改动 + 额外调用；成本最高且预设存在可被替代的收益 |
| **H** 事实回执移除 | 收益是否依赖保留执行事实 | 需新投影变体（保留包+头但移除 execution_receipt） | 记录限制：需 engine 改动；B_bare 已移除回执但也移除动作变更，非纯信息消融；本池回执杠杆未知但主效应近零 |

## 3 执行顺序与冻结约束

1. **先让确认批次（B/R/P/C，64 episode）跑完并用当前冻结源分析+导出**——`analyze_episode` 的确认分支会
   `verify_freeze`，其绑定 `source_hashes()` 覆盖全部 `local_experiments/*.py`；故在确认批次分析完成前
   **不得改动 engine.py/config.py 等冻结源**，否则绑定失配、分析失败。
2. 确认批次分析后，**实现 A（八臂端到端）+ G（声明审计）+ 两项等价证明**，跑全套回归。
3. 在**冻结代表性子集**（按机制覆盖与成本选，非按主结果正负）跑八臂探索性消融（exploratory，不触发 verify_freeze）。
4. B/C/E/F/H/D-3 按上表记录**具体限制**与**不能声称的结论**；若后续在「Reviewer 有杠杆」的池上重做，
   B 与 H 实现成本低，可优先补。
5. 全部源改动定稿、差异审查后，重跑公开清单校验 + 回归 + clean flow，再生成**新的 PUBLIC_MANIFEST**。

## 4 不能声称的结论（诚实边界）

- 不能声称「包装措辞 / 上下文长度 / 事实化改写 / 公开清单 / 回执保留」**解释或替代**了建议生命周期的收益，
