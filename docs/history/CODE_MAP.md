# Historical code and dependency map

This map identifies useful independently authored code and protocol inputs for the earlier branches. Paths use each branch's original repository-relative layout; a release may place that layout under a historical directory. The map is not a license grant or a claim that all neighboring files are suitable for release. Candidate files still require the release's own content and license review.

All listed executable branches use Python's standard library. Python 3.12 is a practical common reproduction target; the contract sandbox documents support for Python 3.10 or later. No model gateway, API key, provider account, package installation, or downloaded upstream implementation is needed. Running the scripts does write local outputs, so use a disposable working copy rather than frozen historical evidence.

## Contract evidence

Include as a cohesive implementation:

- `contract_evidence/contract_sandbox/__init__.py`
- `contract_sandbox/public.py`: public policy types and evidence boundary.
- `contract_sandbox/evidence.py`: contract grid and evidence variants.
- `contract_sandbox/world.py`: deterministic service and hidden event state.
- `contract_sandbox/policies.py`: hand-written controls.
- `contract_sandbox/evaluation.py`: episode execution and violation accounting.
- `contract_sandbox/diagnostic.py`: bounded compatible-world diagnostics.
- `contract_sandbox/run.py`: aggregate and episode output generation.
- `contract_evidence/tests/test_sandbox.py`: implementation and reproducibility checks.

Within this branch, package-relative imports require the whole `contract_sandbox` package. Run from the branch root with `python -m unittest discover -s tests -v` and `python -m contract_sandbox.run --out results`. The tests expect the branch root as the working directory. There are no external data inputs or hard-coded machine-specific absolute paths in the listed code.

No JSON protocol is required at runtime; the authored configuration is in the package. The existing summary and metadata can document history. Generated episode records contain evaluator-only state and must never be fed to a policy as public input.

## Fixed setup outcome audit

Candidate code: `regression_data_audit/audit_labels.py`.

Required plan: `regression_data_audit/audit_plan.json`.

Required external inputs, intentionally excluded from redistribution:

- `single_setup_vectors.md5`
- `single_setup_repository_map.json`

The script verifies both input SHA256 values and expects these files plus the plan beside the script. It performs analysis at module top level, so importing it runs the audit and writes files. Run it only as an explicit offline analysis in an isolated copy: `python audit_labels.py`.

It writes aggregate JSON/CSVs and `frozen_selections.json`. The latter contains selected source task identifiers and must stay outside the public package. The script has no configurable output directory; staging it in a disposable directory avoids modifying an evidence archive or accidentally committing regenerated selections. The corrected implementation uses exact quotient/remainder allocation. The superseded floating-allocation implementation is not a recommended release entry point.

The source-input hashes and public acquisition pages are listed in [Sources and redistribution boundaries](SOURCES_AND_RIGHTS.md). No upstream code or embedding files are imported.

## Deterministic change replay

Core files under `change_replay/`:

- `common.py`: canonical serialization, hashes, and frozen-payload checks.
- `fixtures.py`: authored tool worlds and hand-scripted tapes.
- `hidden_checker.py`: independent terminal-goal checker.
- `replay.py`: boundary recording/replay and direct-function diagnostic.
- `variant_source.py`: authored source variants and AST differences.
- `variants/*.py`: baseline, control, and synthetic-edit source files generated by the variant builder.
- `selection_probe.py`: structural-input-only deterministic selectors.
- `runner.py`: generation, comparison, selection, and aggregate reporting.
- `test_validator.py`: implementation checks and rerun reproducibility.

Required non-code inputs are `public_tasks.json`, `frozen_protocol.json`, and `freeze_manifest.json`. The freeze covers the public tasks, checker source, and protocol bytes. The runner generates `implementation_plan.json`, `variant_manifest.json`, variant source files, and `results/` outputs. Those generated plan/manifests can also be retained as historical evidence, but they are not all pre-existing runtime inputs.

Run `python runner.py` followed by `python -m unittest -v test_validator` from the branch root. The selector runs in a temporary directory with Python's isolated interpreter flag. This is an import/data-flow separation, not an operating-system security sandbox. The variant loader executes only the locally authored hook definitions; it is not a loader for arbitrary downloaded code.

There are no external datasets or fixed machine-specific absolute paths in the core code. Keep local sibling modules together. Tests inspect result files and rerun generation, so their workflow is not read-only.

`package_local.py` is an optional legacy packaging helper, not needed for scientific reproduction. Its recursive inclusion rule is broader than a publication allowlist and can incorporate extra files placed beside the code. Prefer the release's explicit allowlist; do not run that helper over a mixed private/public working directory.

## Constructed decision validity audit

Candidate files under `decision_validity_audit/`:

- `audit_decisions.py`: fixed-pair orientations, exact tests, Holm adjustment, aggregates, and checker fixtures.
- `verify_independently.py`: independent reconstruction without importing the audit implementation.
- `protocol.json`: the frozen analysis parameters.

Both scripts use the same two separately acquired source files as the outcome replay. The main script defaults to a sibling `regression_data_audit` input directory but supports `--input-dir` and `--output-dir`. Use explicit arguments after relocating a branch. There is no machine-specific absolute input path.

Example workflow using relative directories: `python audit_decisions.py --input-dir ../external_inputs --output-dir results_rerun`.

The independent verifier requires an audit directory containing `protocol.json`, `audit_decisions.py`, `results.json`, `family_replicates.csv`, and `audit_replicates.csv`. It verifies the saved script and protocol hashes. To check existing evidence, run `python verify_independently.py --input-dir ../external_inputs --audit-dir .` from an audit directory holding those files. It does not require a redistributed selected-task list.

The main script embeds the exact original protocol hash. Editing a protocol or its expected hash creates a derivative analysis revision; it cannot retain the original freeze claim. Likewise, changing source bytes invalidates the original script-hash relationship checked by the verifier. Public release adaptations must be explicitly versioned and tested without silently rewriting the historical identity. This matters if any protocol wording is sanitized for publication.

## Natural evidence audit

No standalone Python implementation is present in this branch. Its outputs document a static sample and annotation audit, not a runnable benchmark or claim-specific replay. Suitable public derivatives are the aggregate counts and this decision record. The raw selection list, annotations, trajectory excerpts, and separately hosted logs are not needed to communicate the negative finding and should not be copied into this history.

Reconstructing that audit would require separate acquisition of the referenced public objects, byte verification, and renewed rights review. The repository commit does not pin the independently hosted object bytes. A reproducible behavioral replay would need additional environment and patch identity that the audit did not establish.

## Release exclusions and current design separation

Exclude caches, bytecode, prior ZIP bundles, publishing helpers, raw third-party data, task/trajectory identifier lists, raw trace quotations, operational receipts, and source packaging records containing machine paths. Do not copy an entire branch merely because its main script is suitable.

The historical code does not implement or validate the current P/R/C lifetime proposal. In particular, contract recovery and mutation replay fixtures must not become surrogate model results. The planning documents define prospective controls and endpoints, not executable evidence of treatment benefit.
